## 1. プロジェクト概要

**Physics Quest** — 物理を RPG のように攻略しながら学ぶ学習アプリ。
高校物理から始まり、いまは大学1〜2年の範囲(微積分・力学・電磁気)まで入っている。

- コンセプト: **「暗記は絶対ダメ。理解できる喜びを、ゲームの気持ちよさで。」**
- すべての公式に導出レッスンがある。丸暗記を求める説明は書かない(絶対ルール)。
- 問題はすべてオリジナル。過去問・市販問題集のコピーは著作権上禁止。
- ゲーム要素: 敵HPバトル、制限時間、コンボ、ハート3つ、XP/レベル。
- 対象: 高校生〜大学1年生。特に**物理が苦手な大学生(偏差値40程度を想定)**が迷わず進めることを重視している。

### 収録コンテンツ(現在)

| 項目 | 数 |
|---|---|
| 章 | 14 |
| ステージ | 136 (高校27 + 大学109) |
| 演習問題 | 627問(4択、全問ヒント+解説付き) |
| 解説スライド | 1034枚 |
| 解説動画 | 100本(合計約60分。大学の電磁気だけ) |

### 章の構成

- **高校** (5章・27ステージ): 力学 / 熱力学 / 波動 / 電磁気 / 原子
- **大学** (9章・109ステージ): 「数学の武器庫」「力学」「電磁気学」の3分野 × 「初級・中級・上級」の3段階

大学の3段階は、同じ単元を**初級=身近な例から / 中級=記号に慣れる / 上級=きちんと導出する**の順で深めていく作り。
画面では3段階が1枚のカードにまとまっていて、**どの段階からでも自由に始められる**(初級を終えなくても上級を開ける)。

## 3. 技術構成

- Vite + React + TypeScript のWebアプリ。数式表示に KaTeX。
- 進捗はブラウザの localStorage に保存(アカウント不要)。
- PWA対応(オフラインで動く)。
- iOS / Android は Capacitor で同じコードを包んでいる。
- 解説動画は MP4(H.264 + AAC)。音声は VOICEVOX Nemo(男声1)で生成。クレジットは動画内とアプリ内の両方に表示済み。
- レッスンの読み上げは端末の音声機能(Web Speech API)を使う。自動再生はしない。

### 主要ファイル

| ファイル | 役割 |
|---|---|
| `src/types.ts` | データの型(章・ステージ・レッスン・問題) |
| `src/content/` | 学習コンテンツ本体。高校は `mechanics.ts` など、大学は `levels/intro-*.ts` `levels/middle-*.ts` `univ-*.ts` |
| `src/content/index.ts` | 全章をまとめて組み立てる |
| `src/components/QuestMap.tsx` | トップ画面(章一覧) |
| `src/components/LessonView.tsx` | レッスン画面 |
| `src/components/EMVideoLesson.tsx` | 動画レッスン画面 |
| `src/components/BattleView.tsx` | バトル画面 |
| `src/components/figures/` | 図解(SVG)。大学編は `figures/levels/` |
| `public/media/em/` | 動画100本(mp4 + ポスター画像 + 字幕データ) |
| `scripts/audit-*.mjs` `scripts/test-*.mjs` | **品質チェック**。コンテンツの間違い・数式の崩れ・図の不足などを自動で見つける。GitHubに push すると自動で走り、落ちるとWeb版が更新されない |

### コマンド(ユーザーのMac: ~/physics-game-)

```
npm run dev          開発サーバー
npm run build        ビルド
npm run sync         ビルド + ネイティブへ反映
npm run open:ios     Xcodeで開く
```

更新の反映手順: コードを直したら `git add -A` → `git commit -m "..."` → **`git push`** でWeb版は自動更新(数分)。
**commit しただけでは反映されない。push まで必要。**(過去にこれで「何も変わっていない」となった)
iOSは加えてMacで `git pull` → `npm run sync` → Xcodeでビルド。

## 6. 残っている作業

### 1. ★最優先の判断: 上級編から消えた216枚のスライドを戻すか

ChatGPTの変更で、大学・上級編のスライドが **398枚→182枚** に減った(例: ベクトルの単元が11枚→2枚)。
一緒に品質チェックの基準も緩められている。

**この判断をユーザーに2回聞いたが、まだ答えをもらっていない。** 作業を再開するときは、まずこれを決める。

Claudeの推奨: **戻す。** そのうえで、初級・中級を書き直す(下の2)。理由は、いま初級・中級・上級が「同じ文章の長さ違い」になっていて、本来あるべき「深さの違い」になっていないから。

### 2. 初級・中級の39ステージを書き直す

大学編のステージは、手で書いたものと、上級から機械的に移したものの2種類がある。品質に差がある。

| | ステージ数 | 1ステージのスライド | 問題数 |
|---|---|---|---|
| 手で書いたもの | 41 | 約10枚 | 約4〜5問 |
| 移したもの | 39 | 約4枚 | 約1問 |

「移したもの」39ステージ(初級21・中級18)を、手書きと同じ水準にする:
- スライドを8〜10枚、問題を4問に増やす
- 見出しを「〜とは?」のような疑問形にする
- 「復習:」で始まるタイトル(15ステージ)を直す
- 初級から ω・φ・連鎖律のような難しい記号を外す

### 3. 実際にプレイして見つかったつまずき箇所(手書きステージ)

- `ui-average-to-now` の問2: まだ教えていない 1.2² を使わせている
- `ui-curve-tiles`: 小数が多すぎて計算で止まる
- `ui-effective-component` の10枚目: θ と内積を同時に出していて重い

### 4. 動画について気になっている点(バグではない)

- 動画のあるステージは、**スライドの代わりに動画が最初に出る**ようになった。元のスライド1枚あたり10〜13秒のペースで、物理が苦手な学生には速いかもしれない。式や図は「この場面の式・記号・図を確認する」を開けば見られる
- 動画の字幕が、スマホを縦に持つと小さい(横向き・全画面で見る案内は出ている)
- 動画があるのは電磁気だけ。数学・力学にはない
- 動画が再生できない端末では、自動で元のスライドに切り替わる(この仕組みは確認済み)

### 5. アプリの容量

動画のせいでアプリのサイズが **16MB→107MB** になった。App Store の制限には全く届かないので提出は問題ない。
ただし、Web版の置き場(gh-pages)は「古いファイルを消さない」設定になっているので、
**動画を作り直すたびに古い動画が残り続ける**。動画を作り直す前に、Claudeに「古い動画が残らないようにして」と頼むこと。

## 7. 設計上の絶対ルール(変更しないこと)

1. **導出のない公式を追加しない**。「覚えましょう」という説明文を書かない。
2. 問題は**必ずオリジナル**で作る。過去問・市販問題集の転載禁止。
3. `appId: app.physicsquest.game` は**公開後は変更不可**。
4. 個人情報を集めない設計を守る(アカウント不要・localStorage・匿名計測のみ)。
5. ネイティブ版でAIチャットを出さない(審査リスク。`src/config.ts` の `SHOW_AI_CHAT` で制御済み)。
6. リポジトリ名の変更・privateへの変更をしない(Pages URLが死ぬ)。
7. **大学編の段階を「前を終えないと開けない」仕様にしない。** 既存のステージID・問題ID・進捗データは維持する。
8. 数式の中に日本語を直接書かない(フォントが崩れる)。必要なら `\text{}` で囲む。
9. コードを変えたら、push する前に `npm run build` と品質チェック(`npm run test:lessons` など §3の表)を通す。
