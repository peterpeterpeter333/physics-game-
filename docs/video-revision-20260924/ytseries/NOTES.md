## A. ユーザーからの要望（テーマ別・これまでの全部）

### A-1. 教材全体の見直し（大学力学）
- 偏差値30の学生の目で、高校と大学の力学教材を点検する（日本語の分かりにくさ、説明不足、順序、面白さ、アニメの質）。
- 点検は高校・大学の両方、変更は大学編だけ。
- 3Blue1Brown を参考に。音声は Nemo、読み間違いがないようにふりがな（読み）を付ける。

### A-2. 見ていて気持ちよく、頭を使わずに追える動画
- わかりやすいだけでなく、頭を使わずに見られて、見ていて気持ちいい（ドーパミンが出る）ように。
- 軽いアルファ波の BGM と効果音。
- 3Blue1Brown は抽象的すぎるので、Lesics や Sabin 機械工学のような具体例中心に寄せる。
- ひとまとまり説明したら、考えをまとめる間を置く。抽象的な式の場面は特に間を長く。
- 音声の不自然な伸ばし（「時速ー８０キロのー」）をなくす。

### A-3. 具体と抽象を行き来する
- 具体（現象）→ 抽象（数学）→ 具体。例：「この時の空気抵抗は速度に比例するので kv とおけます」。

### A-4. 難しさから逃げない
- 「覚えなくて大丈夫」は使わない。難しい式の意味をちゃんと解説する。
- わかりやすくする ＝ 簡単にする、ではない。「難しい内容を理解するための足場を作る」。
- 読めない式を先に見せ、少しずつ解読し、組み立て直し、使ってみる構成も可。

### A-5. 台本の組み立て（社会系動画の分析から）
- 意外な現象から始める。動画全体を一つの問いで貫く。
- 文と文を「そして」ではなく「だから・しかし・そこで」でつなぐ。
- 名前を付ける前に体験させる。頭の中の組み立てを絵が代わりにやる。
- 同じ考え方を別の現象にも使ってみせる。最後に冒頭へ戻り「今なら分かる」と感じさせる。
- 予想させる問いで面白さを作る。本物の初心者に見てもらって確認する（未実施）。
- 一番大事なのは、次にこの話をする理由が自然に分かる台本。

### A-6. マクスウェル方程式の長編（v2）
- マクスウェル方程式を終着点に、高校の初歩から積み上げる。20分以上でも可。
- レビュー70項目と「面白くない」12項目を全部直す。分からない理由を「前提知識の不足」と「論理の飛躍」に分けて洗い出す。

### A-7. 深く学ぶモードで本当に深める（v3）
- 「なぜ？」を追うと最後は数学の公式や物理の原理という土台に行き着く解像度。
- 点検72件：実験で確かめた法則と導いた結果の区別、等号の正確さ（平均か瞬間か、近似か）、前提条件とモデルの明示、一般化の段階を分ける。

### A-8. 数式を理解するための「考え方の補助線」（v4）
- 数式を理解するところが分かりにくい → 比喩・例え話などの補助線を入れる。
- 図と式の一項の対応を見えるように（補助線レビュー48項目は参考。全部に従わなくてよい。良い補助線は採用）。

### A-9. 全動画の品質基準（ChatGPT 作成プロンプト。原文は「ユーザー指示の原文」）
- 基準動画は Maxwell v4。ただし誤りや改善点は踏襲しない。
- 最初に棚卸し。前提知識と、それを説明している動画を対応づける。上級で突然前提にしない。同じ前提説明を全動画で繰り返さない。
- つまずき A（前提知識がない）と B（図と式の対応・次の一手の理由を自分で補う必要がある）を分け、最小限の補助線。
- 補助線の候補：数値例、同じ番号・色の対応、拡大・投影・分割・重ね合わせ・回転、固定するもの／変えるものの対比、一操作の前後比較、比喩。
- 比喩は「何が何に対応し、何は対応しないか」を示し、必ず元の現象と式に戻る。比喩の説明が要るなら別の方法。同じ概念には同じ比喩。
- 構成：現象・疑問 → 予想 → 図で調べる → 式を組み立てる → 計算 → 元の現象に戻る。機械的に繰り返さなくてよい。最後に次への問い。
- 数式：何を求めたいか／各文字の意味と単位／図のどこか／既知と未知／なぜ掛ける・割る・足す・積分するか／何が分かったか。記号の説明は初出の近くに短く。式変形は動きで（代入する項、両辺に加える量、約分で消える因子）。ナレーションは操作の目的を言う。
- 混同しない：有限の近似と極限の等式、スカラーとベクトル、半径と位置の変化、量と変化率。定義／実験に支えられた原理／仮定／導いた結果を区別。
- 画面の主役は一つ。図の話をしている間はその図が映っていること。上下・左右・手前奥・正負・色・番号を映像と語りで一致。視点の回転と物体の運動を区別。3D は意味があるときだけ。
- 音声：読み間違い・不自然な空白・文章途中の切断を確認。字幕と読みは別管理。主語の省略で「何が？」とならないように。0.9倍速標準、同期を維持。
- 基準動画から直す点：6 N ÷ (2 A × 3 m) ＝ 1 N/(A·m) ＝ 1 T（1 N ではない）／部屋・改札の比喩で電荷保存とガウスの法則を混同させない／k→ε₀ は「両替」ではなく ε₀＝1/(4πk) の定義／線積分で「扇風機の風が円周方向に吹く」と思わせず、一歩を半径方向と接線方向に分ける／複数の項を一度に足して消さず一つずつ。
- 元の動画は新版の確認が終わるまで削除しない。GitHub への push と App Store 提出は別途指示まで行わない。

### A-10. 大学編 YouTube シリーズ（現在の作業）
- 対象は大学編だけ。まず1分版の見本 → 合格（微分・初級）。
- 既存の動画は内容を把握するだけ。流用しない。
- 単元×レベル（初級→中級→上級の順）ごとに約5分の動画を1〜10本。説明の細かさは分野の難しさで変えてよい。微分・初級は2本がちょうど良い。
- 横長（1280×760）。全部を一つのフォルダに。
- 各動画は単独で完結しつつ、前の本の最後の問いから始め、次の本への問いで終える。

## B. 表記と色の約束（シリーズ共通）

- ベクトルは太字（𝐀、𝐅、𝐄、𝐁、Δ𝐫）、大きさ・長さは細字。外積 𝐀×𝐁 と長さの積は「A ×（B sinθ）」のように区別。
- ⊙＝画面の手前向き、⊗＝奥向き。右ねじ（ふつうのねじ）：反時計回りでゆるんで手前。
- 色：位置 x 水色、速度 v 紫、加速度 a 赤、力 F 緑、時間 t・周期 T 金、エネルギー（U・K・仕事）橙、運動量 p 桃、ω 桃、角度・位相 橙、強調 黄、誤り 赤。電磁気：𝐄 水色、𝐁 橙、電流 I 緑、電圧 V・起電力 ℰ 紫、電荷 q 桃、正電荷 赤、電子 青。
- トルクの記号は N（アプリの表記）。起電力は ℰ（読みは「起電力」）、単位 V。
- 1 T ＝ 1 N/(A·m)。ε₀ は定義した定数。
- 字幕では ẋ・ẍ を使わず d²x/dt²。「x×x」は「x × x」と空白を入れる。字幕の Sₙ の下付き ₙ はフォントに無い → 「Sn」。e^(−kt) のような ASCII 表記は避ける（初級08-2 に残っている）。
- 同じ文字を二つの量に使わない（中級03-2 で高さ h と刻み h が重なった → 刻みを Δx に）。

## C. 制作中に見つかって直した点（今後も必ず確認）

- 字幕で数字・単位・式が行の途中で割れる（「6｜.00 m」「12.│5」「0.02｜秒」「T＝｜π」など）→ 文を短くする。レンダラと同じ折り返しで事前チェックする。
- 字幕と画面の食い違い（位置グラフを映しながら「このグラフは速度です」など）。
- 動画の中で導いていない式を画面に出す（初級01-2 の「v＝10t」→ 導く1文を追加）。
- 「π＝180°」→「π rad＝180°」。
- 向き・符号：⊙/⊗、右ねじ、𝐯×𝐁、レンツの向き、電流と電子の向き、電池の極、裏から見たときの見え方。外積の成分計算で一つずつ確かめる。
- ラベルの重なり、はみ出し、欠け、カードが軸ラベルを隠す、`tex()` に日本語を入れて崩れる、英語の表示（「total」など）。
- 文字サイズは 22px 以上。
- 前の本・後の本との言い回しのずれ（最後の問いと次の最初の問いを一致させる）。
- 内容の重複：前の単元で教えたことは短く振り返るだけにする（例：仕事と内積、単振動と振動の方程式、角運動量と外積）。
- 前提の不足：その単元で初めて必要になる概念は冒頭で補う（例：電気束をガウスの前に、角速度 ω を慣性モーメントで先に、磁場をローレンツ力で）。
- 「ここでは使うだけ、詳しくは○○の回」と正直に言う（ma＝F、フックの法則、T≈2π√(L/g)、v²/r など）。
- 計画外の追加は報告する（初級15 の 𝐋＝𝐫×𝐩 予告、初級26 の一周の和）。

## D. 音声（読み・アクセント）の注意

- kana（アクセント句表記）はすべての句に `'` が必要（無いと HTTP 400）。文中の「？」も 400 → 「、」にする。
- 長音の綴りはエンジンに合わせる（オ／ウ、レイ／レエ）。
- 語頭の「は」は ハ（ハバ、ハイル、ハチ）。「18」は じゅうハチ。
- アルファベットの C は シイ／スィー（エンジンが「スィー」と読む）。
- 「平均」が エイキン と読まれた → ヘイキン。いろは・せいは なども誤読 → 言い換え。
- 数字を仮名で書くと誤読することがある（「いちななご」）→ 区切る。
- 読みの機械検査（check-readings）0件、prosody 終了0 を必ず確認。ただし耳での確認は別（まだ全本未実施）。

## E. 作業の進め方の注意（技術）

- 音声エンジン Nemo は /private/tmp に置くと再起動で消える → `~/Library/Application Support/physics-quest-tools/` に置いてある。
- mix-audio.py の BGM が1サンプル短くて落ちる不具合 → `n = len(voice)` に修正済み。
- 作業エージェントがバックグラウンドの待ちで止まる（600秒無反応）→ 長いコマンドは前面で実行させる。
- 複数のエージェントが同じ作業用フォルダ（scratchpad）を使うとファイルが上書きされる → 各自のサブフォルダを使う。
- review シート（mxr-review）は1 cue につき1コマ（終わりの時点）しか見えない。動きの途中は shots.mjs で個別に確認。
- 確認の記録は正直に：台本検算／読み・kana／静止画の目視／デコード検査／通し再生・聴取 を区別。やっていないことを書かない。
