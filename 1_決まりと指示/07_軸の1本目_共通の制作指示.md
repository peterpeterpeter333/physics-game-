### 作り直しを減らすための決まり
- **時刻は、cue キーと語の時刻（`T(key,'カナ')`）で決める。** コマ番号や秒の数を直に書かない。直に書くと、直すたびに広く壊れる。

- **Blender は、1回の起動で多くのコマを書く。** コマごと・場面ごとに起動し直さない。並列は2本まで。
- **確かめの記録は、11章の表と検査の json だけでよい。** 全コマのハッシュの表や、証明のための大量のファイルは作らない。
- **撮影の表を shot-plan.json にする（S0）。** 回ごとの指示書の撮影の表を、`<cache>/shot-plan.json` に書き写す。形は `[{"cue":"cue キー","word":"合わせる語（台本の KANA のカナ。無ければ書かない）","occ":0,"primary":"主役の名前","minWidth":0.5}]`。主役の名前は、primary.json の名前と同じにする。全画面の顔の行は書かない。
- **主役の外枠を出す。** 場面のファイルの `anchors(t)` に、毎コマの主役の名前と画面上の外枠を足す。書き出し先は `<cache>/blender/primary.json`、形は `{"コマ番号": [x0, y0, x1, y1, "主役の名前"]}`。Claude の自動検査が、主役の大きさと「声が名前を言った物が映っているか」を、これで測る。

### 6.1 理解のための設計（一番大事）
- 説明の間は、カメラを止める。止めたまま、手・物・札の動きで見せる。
- カメラを動かすのは、次の3つの時だけ。
  - 場面の切り替わり
  - 何かを見せる瞬間（物が置かれる、組み上がる、つぶれる）
  - 笑いの所
- カメラが動いている時間は、全体の2割以下にする。
- 計算や答えの札は、声がその語を言い始める時刻に出す。声より先に出さない。
- 1段の計算のあとは、物を止めて間を見せる（台本の pause の間）。
- 三つの見方の札（具体例・たとえ話・○○側から）は、台本の view の区間ずっと出す。文言は正本どおり（「破る側から」「作る側から」「確かめる側から」のどれか）。
- 論理の筋の札（仮説 → もし正しいなら → 予言 → 事実 → 判定）は、声に合わせて1枚ずつ出す。前の札は出したままにする。
- 数を出す札は、**途中の段を全部**出す（例「26.5 × 26.5 × 3.14 ≒ 2200」）。答えだけの札にしない。台本で声が言う段は、全部画面にも出す。

### 6.1b 大事な物・変わる物は、必ず寄って見せる（2026-10-26 追加。ユーザーの指摘）
- 見る人に「頭の中で補わせない」。声がその物の名前を言う時、その物が画面に大きく、はっきり出ていること。
  - 例：「北極星の高さ」と言うなら、北極星そのものを画に入れ、見上げる線と角度を見せる。「出っぱりが隣を押す」と言うなら、出っぱりと歯車に寄り、押す瞬間を光とスローで見せる。
- 何かが変わる瞬間（傾く・押す・開く・閉じる・流れる・つぶれる）は、カメラが寄って、その変化が画面の横幅の半分以上を使う。
- 小さな物の向きや動きを見せる時は、寄りの画か、2D の拡大の丸（虫めがね）を使う。
- 細い線・小さな粒・淡い色は、背景（机の木目・壁）と違う色で、太くする。主役だけを照らし、まわりを少し暗く落としてよい。
- 物理的にあり得ない置き方をしない（例：鉄の粉は空中ではなく、紙の板の上にまく）。

### 6.2 机の世界
- 机・部屋・光・ぼけ・手・カイとミオの顔は、1-1 第6版と同じ（desk_lib の部屋と光をそのまま使う）。回ごとに色温度や机を変えない。
- 真上からの画は、文字を読ませる場面だけにする（全体の2割以下）。
- それ以外は、仰角25〜55°で、壁・窓・植木・机の手前が少し映り、背景がぼける画にする。
- **物は、画面の横幅の4〜7割の大きさに映す。** 小さく遠い画にしない（6.0）。
- 同じ構図が8秒以上続く所は、物か手を動かすか、寄りと引きを切り替える。
- 物の少ない画面（机の木目ばかり）を、2秒以上続けない。
- 冒頭の0秒から、手か物が動いている。最後の1〜2秒は、冒頭の物に戻る（回ごとの指示書に書いた物）。
- 1つの回の物は、机の上の決まった場所に置き、場面が変わっても勝手に動かさない（回ごとの指示書の「机の上の置き場所」）。見る人が「さっきの物」を同じ場所に見つけられるようにする。
  - 出番が1つの場面だけの物（例：D-1 の風船、銅の半球）は、出番まで置かなくてよい。出番の後は、机の奥へ滑って退くか、そのまま消してよい。置き場所が重なる物どうしは、同時に机に出さない。
  - 置き場所の表の数字は目安。画で重なって見えるときは、重ならないように少し動かし、撮影台本に書く。

### 6.3 文字と札
- 文字は最小 36px。
- すべての札が、x 40〜1040、y 110〜1600 に収まる。札の字が、札の地からはみ出さない（文字の幅を sharp で描いて測り、地の幅を決める）。
- 年と場所の札は左上 (40,130)、見方の札はその下、注記は (40,1440)。
- 冒頭の0〜2秒は、題の札と一緒に、軸の札「B 電気と電波 1」のように、軸の記号・軸の名前・何本目かを出す（題の上、小さく 36px）。
- 勝負の札の 2D 版は右上で、点が入る前後だけ出す。札の名前は、回ごとの指示書の「勝負の札」の文言。
- 3D の文字は、大きな数字や1文字のタイルなど、遠くからでも読める物だけにする。読ませる説明の字は、2D で重ねる。

### 6.4 色の意味（シリーズで固定。変えない）
- 正しいは緑の○、まちがいは赤の×、強調は黄（`#ffd23f`）。
- カイの手は青（`#3d63c9`）、ミオの手は桃（`#e8789c`）。
- 回ごとの色の意味は、回ごとの指示書に書く（例：B-1 の磁石は N 赤・S 青）。

### 6.5 音
- 声の下に、音楽を途切れず流す。全体は −14 LUFS 前後で、無音（−35dB 以下が0.25秒以上）は0回。
- 効果音は小さく使う。回ごとの指示書の効果音の表に従う。
- E-1 の事故の場面（行1〜6）には、明るい音・笑いの音を入れない。

- **BGM は、声と重ならないようにする（2026-10-27 追加。ユーザーの指摘「BGM が解説とかなり被る」）。** C-1 で直したやり方（`W/scripts/umech/mix-chain-desk-audio-c1v1_claude_bgm_20261027.py`）にそろえる。
  - 声がある間は、BGM を 90％ 下げる。下げる量は、声の一番大きい所ではなく、声の小さめの所（声の大きさの下から25％）を基準にして、声がある間は必ず深く下げる（desk_audio_lib の duck_under_voice は使わず、この関数を写して使う）。
  - ずっと鳴る和音の帯（bed のパッド）も、声がある間は 75％ 下げる。声のない間（間・場面の切り替わり）は、今の大きさで流してよい（無音にしない）。
  - 声がある間は、速い音型（16分音符のマリンバ、bright=1）や、音量を上げた区間（×1.25 など）を使わない。山場（solve）でも、ふつうの伴奏にする。盛り上げは、声のない間（間）で行う。
  - 確かめ方：BGM だけを別に書き出し、声がある1秒ごとの「声と BGM の差」の中央値が 15dB 以上（C-1 の直しで 17.9dB）。最終報告に数値を書く。

### 6.5b 音楽の区間（台本の music の印）
- 台本の冒頭コメントに、この回の music の割り当て（solve・solved・dark・toll・after）が書いてある。それに従う。
  - 1-1 の mix は、区間が solve → solved → dark → toll → after の順に並ぶことを前提にしている。台本の割り当ては、この順を守って置いてある。
  - 鐘の位置（1-1 の mix の 'end:exec'）を、この回のキーに読み替える：B-1 'odd:mio'、C-1 'dad:price'、D-1 'next:100'、E-1 'dr:cause'（台本の冒頭コメントでも確かめる）。
  - 効果音（缶がつぶれる音など）は、音楽の区間ではなく、回ごとの指示書の効果音の表で入れる。
- after の後は、元の音楽（base）に戻る。
- 1-1 の mix（mix-chain-desk-audio-1-1v6.py）は、鐘やカチの位置を 1-1 の cue キーで直に書いている。この回の mix では、それを全部この回の cue キーと時刻に替える。1-1 のキーを1つも残さない（`grep c11v6-` で0件を確かめる）。

### 6.6 字幕と顔
- 字幕と顔は、台本ファイルの cap・face に従う。仕組みは desk-frame.mjs がやるので、あなたが描く必要はない。
- 全画面の顔のアップが出ている間は、回ごとの札を出さない（desk-frame.mjs の約束）。
- 顔の表情は8つだけ（desk-faces.mjs）。正本の「考え顔」「真顔」など、8つにない顔は、台本ファイルで近い表情に置き換えてある（例：考え顔 → komaru）。台本ファイルの face に従う。

### 6.7 共通の部品の、1-1 の文言が直に入っている所（回ごとに自前で持つ）
- 見方の札の色の表（desk-overlay-lib.mjs の VIEWCOL）には、「具体例」「たとえ話」「破る側から」しかない。「作る側から」「確かめる側から」は、この表にないので、そのままでは札の左の色の帯が出ない（色が undefined）。回の overlay の中に、自前の色の表を持つ（作る側から＝橙 `#f0a040`、確かめる側から＝緑 `#5aa469`。破る側から は 1-1 と同じ）。desk-overlay-lib.mjs は変えない。
- 勝負の札の 2D 版（scoreHUD／chain-score.mjs）は、文字が「作る側／破る側」に固定されている。台本ファイルの score は `{make, brk}` の形のまま、make＝左の名前、brk＝右の名前として入れてある（各回の指示書の「勝負の札」）。回の overlay で、その回の名前の札を自前で描く。共通の部品は変えない。

## 7. 撮影の指示
- 回ごとの指示書の7章の表に、正本の行ごとに書いてある。
- 時刻は「<回>_cue時刻一覧.md」の秒を使う。「合わせる語」は、その語を声が言い始める時刻（`T(key,'カナ')`）。カナは台本ファイルの KANA の表記で探す。見つからないときは、時刻の一覧の「主な語の時刻」を使う。それもなければ、cue の割合で決め、撮影台本に書く。
- 姿勢は `P(見る点, 距離m, 方位°, 仰角°, レンズ)`。場所は机の座標で、机の中央が原点、x は右、y は奥、z は上。
- 表にない細かい所は、見本（1-1）の同じ種類の場面に合わせる。

## 8. 部品の決まり
- 既存の部品は `desk_lib.py` の関数を、そのまま使う。
- どの部品も、次の決まりに合わせる。
  - 1-1 と同じ光・同じ材質の作り方（mat・wood・imgmat）・同じ縮尺。
  - 角を丸める（bevel）。温かい模型の雰囲気にし、写真のようにはしない。
  - 3D の文字は Arial Rounded Bold。
  - 物の大きさは、机（1.6×0.9m）の上に置ける模型の大きさにする（大きい物も、縮めた模型にする。例：炭鉱の断面、船、地球儀は、20〜35cm）。
- 各部品は、カタログと同じ撮り方の画像を書き出し、`部品カタログ画像/` に足す。カタログの md にも追記する（既存の記述は消さない）。
- 人形（人物）は、1-1 の人形の形（丸い頭、筒の体、色の違い）にそろえる。顔は描かない。人物の見分けは、帽子・ひだ襟・色・持ち物で付ける。

## 12. 問題編の準備（いまは作らない。あとで入れられるように）
このシリーズは、物理の RPG の一部です。あとで、各回の最後の「挑戦」を、遊べる問題（問題編）にするかもしれません。そのときに作り直さなくて済むように、次を用意してください。
- `desk_<id>.py` に、次の2つの関数を作る。
  - `challenge_setup()`：挑戦の場面の物だけを、机の上に置いた状態にする（声の時刻に頼らない。t を使わない）。
  - `answer_state()`：答えが分かった状態（例：針が上を向く、腕が3回落ちた後、富士山で矢印が短い、地球儀の東30度の印）にする。
- それぞれを、1080×1920 で1枚ずつ書き出す：`<cache>/problem/挑戦.png`、`<cache>/problem/答え.png`。
- `<cache>/problem/problem.json` に、正本の「問題編への接続」の節（問題・答え・解き方の段・予備の問題）を、そのまま写す（日本語は変えない）。使った部品の名前の一覧も入れる。
- 予備の問題の画は作らなくてよい。
