## 原因と検査範囲

- 提供台本の読み仮名を区切る空白をNemoが `pause_mora` に変換していた。例「コップの みず …」では、読点1個に対して複数の休止が生成される。
- 音声エンジンの前後無音に加えて、生成処理が毎文0.6秒・毎場面1.2秒を追加していた。
- `audit.json` は既存MP4全384本の信号・字幕・読み指定を検査した結果。`script-audit.json` は提供台本1,115文のエンジン解析。全編を人間が聴き通した検査ではない。

## 既存MP4への処置

再合成で読みやアクセントが変わることを避け、既存の発話部分を維持する。-50dB以下の実測無音についてのみ、空白に対応する区間・文境界・場面境界を検査した。

- 単語区切り：エンジンのモーラ時間と実際の無音が一致する場合だけ短縮。約0.10秒とフレーム丸め分を残す。
- 文境界：約0.42秒、場面境界：約0.85秒を残す。数式の読点、意味上の間、発声中の区間は対象にしない。
- 24fpsの同一フレームを音声・映像から除去。音声は24kHzで1フレーム=1000サンプルとし、字幕・場面境界・本編への復帰時刻も同じ変換で更新。
- 元MP4・JSONは `/private/tmp/physics-fluency-repair/originals` に退避。再実行では二重に短縮しない。
- 各出力を全デコードし、動画の尺とメタデータの差が0.12秒以内かを検査してから差し替える。
- 初期の60秒試作1本は文単位の字幕時刻がないため、場面境界だけを検査・修正。通常の教材・問題動画383本とは検査粒度が異なる。

## 今後の生成処理

`narration_fluency.py` で読み指定の空白に対応する `pause_mora` だけを削除。モーラ・アクセント・ピッチは変更しない。対応が曖昧なら生成を止め、黙って読点を削除しない。全1,115文で対応が一致した。

毎文の追加無音を0.16秒、毎場面の追加間隔を0.55秒に変更し、エンジン側の前後無音も短縮。読み速度0.90は維持。キャッシュのバージョンを更新し、以前の区切りが多い音声を再利用しない。
